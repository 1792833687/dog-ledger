# 狗账

**给两个合伙人记犬只买卖账的手机网页。** 用手机浏览器打开、加到桌面就像一个 App。
数据只存在这台手机自己的浏览器里，**不联网、不上传、没有服务器**，也不做多人同步或云端备份。

线上地址：**https://1792833687.github.io/dog-ledger/**

## 五个页面

| 标签 | 干什么 |
| --- | --- |
| 算 | 建一个进狗批次，填各项成本，算出卖到多少钱才保本；顺手记当天抓回来的狗，或者直接**收货**建批次。 |
| 狗 | 每只狗的状态与去向（在栏 / 已卖 / 死亡 / 退回），卖出与死亡的数字从这里进账。页顶是**预定单**：狗还没到月龄、先跟卖家说好，就把卖家、约几只、哪天去收记下来；到日子会提醒「该去收了」，收到狗时一键转成一个批次（实收几只、每只多少钱）。 |
| 检 | 每只狗的检疫证明记录 —— 平台要求有证明，没证明就卖不掉。 |
| 钱 | 合伙人的池子：注资、垫付、分红，以及池子当前余额。最近流水**每一笔都能就地改或删**（改金额、日期、经手人、支出类别、备注；删一笔销售流水会把那只狗改回在栏）。 |
| 报 | 分账（每人应分 / 已分 / 还垫着多少）、批次盈亏排行、钱花在哪了、死亡率趋势，生成对账单图片发伙伴。 |

## 先做、后补账

收货那一步**只记收购款**（每只一笔）。运费、疫苗驱虫、检疫申报、病死犬处理费这些，往往是回来之后才真正付掉、也才记得清 ——
所以它们在批次详情里的**「补成本」**填一次就好：运输是一整批一笔，其余三项填「每只单价」，系统按这一批实际有几只狗摊开成流水。
补成本**只新增，不动你已经手记的账**；哪一批还没补过，「狗」页里那一批会挂一行橙字提醒你「保本价现在是偏低的」。

## 本地跑

```bash
npm ci
npm run dev
```

改完代码过三道门禁：`npx vitest run`（测试）、`npm run build`（类型检查 + 打包）、`npm run lint`（0 warnings 才算过）。

## 数据在哪、怎么备份（**最重要的一节**）

账本存在浏览器自己的数据库（IndexedDB）里。**清了浏览器数据、换手机、卸载浏览器，账就没了，找不回来。**
所以不定期去「报」页面最底下点**导出备份文件**，把下载到的 `狗账备份-YYYY-MM-DD.json`
立刻发到微信「文件传输助手」或存进电脑；换设备时在新手机上打开本页，用**从备份恢复**选中那个文件。
三天没备份，「报」页上方会挂一条黄色提醒。
